# QASPER Online Control Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run reproducible QASPER random/grouped baseline and online-policy-enabled experiments through the real vLLM/LMCache control path and archive one audited result package.

**Architecture:** Reuse `Task1QasperWorkload` as the sole dataset adapter and `run_real_benchmark.py` as the sole request/metric/context producer. A shell orchestrator launches a version-locked LMCache vLLM EngineCore with a per-run `RuntimeControlHost`, executes baseline and enabled conditions, exports artifacts, evaluates QASPER quality, validates paired evidence, and writes a suite summary.

**Tech Stack:** Python 3.12, unittest, Bash, vLLM 0.23.0, LMCache 0.4.7, DGX Spark.

## Global Constraints

- Never modify QASPER request content, sample set, or published order; only select a published `random` or `grouped` workload.
- Use vLLM `0.23.0`, LMCache `0.4.7`, and `LMCacheConnectorV1` only.
- Keep all secrets in a mode `0600` runtime env file and never copy them into manifests or reports.
- Do not push `origin` or merge into `main`.
